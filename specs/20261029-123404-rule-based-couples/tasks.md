## Conventions binding every task

- **RED first** in every task that changes behaviour: write the test, run it, watch it fail for the stated reason, then implement. A test never seen failing is not a test. Tasks marked *refactor* or *guard* say how the test is proven instead (mutation proof).
- **Mutation proof** where a task says so: introduce the named mutation, watch the test go red, revert.
- **Reuse statement** in the commit body of every task that adds a function: "Searched [where] for [what]. Found [X], reused / Found nothing, built new." The searches are already done in `plan.md`, "Architectural placement and reuse"; copy the relevant one.
- **Taste thresholds**: every function at most about 40 lines and 3 levels of nesting; one way to do each thing; typed errors; docstrings in English with the citation, equation number and verification status of every formula and constant (project CLAUDE.md, "Code Comments and Docstrings").
- **One task, one commit**, checkbox flipped in that commit, except inside a **commit group** (`G<n>`, plan PD-19): the tasks of a group are done and flipped one at a time, and one commit is made at the last task of the group, because the doc-sync rule requires the whitepaper chapter in the same commit as the code. A commit that touches a module of the doc-sync table without changing its model (an unused helper, a test-only change) says so in its `CHANGE:` paragraph.
- **Commit messages**: Conventional Commits in English through `git-commit-assistant`, no AI reference, no `Co-Authored-By`, no emoji.
- **Escalation**: anything not derivable from this file, the plan and the spec (an unforeseen edge case, a wrong assumption, a symbol that does not match) stops the task and goes to Opus. Never invent.
- **Markers**: `[P4]` = needs the Plan 4 code merged into `develop` and realigned here (T001). Tasks without `[P4]` touch only code that is identical on `develop` today and could be done before the realignment if the Trinity lifts the "phase 5 after the Plan 4 merge" gate; by default they are done in the order below, after T001. `[US1]`, `[US2]`, `[US3]` = user story. `[Opus]` = phase-6 or judgment task, not for the Sonnet implementer. `[COORD]` = done by the coordinating session that owns the build map and the issue.
