## Conventions binding every task

- **RED first** in every task that changes behaviour: write the test, run it, watch it fail **for the stated reason**, then implement. A test never seen failing is not a test. Guard tasks say how they are proven instead (mutation proof).
- **Mutation proof** where a task says so: introduce exactly the named fault, run the named test, watch it go red, revert, run it green again; write "mutation: <fault> -> red, reverted" in the commit body.
- **Bars** (every code task restates them): functions about 40 lines at most, nesting at most 3 levels, no catch-all `except`, typed errors that callers decide by type, no dead code, no duplicated logic, every formula and constant cites its source and verification status in a comment, English identifiers, docstrings in English.
- **Reuse statement** in the commit body of every task that adds a function, copied from plan "Architectural placement and reuse".
- **One task, one commit**, checkbox flipped in that commit, except inside a **commit group** `G<n>` (plan PD-07): tasks are done and flipped one at a time and one commit is made at the last task of the group. A commit that touches `fertility.py` without changing the model (G1, G2) says so in its `CHANGE:` paragraph.
- **Commit messages**: Conventional Commits in English through `git-commit-assistant`; no AI reference, no `Co-Authored-By`, no emoji. Scope `demography` unless the task names another.
- **Escalation**: anything not derivable from this file, the plan and the spec (a symbol that does not match T003, a number that does not reproduce, an unforeseen test impact) stops the task and goes to Opus. Never invent a value.
- **Markers**: `[CPL]` = needs `develop` to contain Plan 4 **and** rule-based couples, merged here by T001; every task of this file is `[CPL]` by default (D-MF-06), the marker is written only where the couples code is read directly. `[US1]`, `[US2]`, `[US3]` = user story of the spec. `[Opus]` = phase-6 or judgment task, not for the Sonnet implementer. `[COORD]` = done by the coordinating session that owns the build map. `[P]` = parallelizable with the neighbouring task (different files, no dependency).
- **Whitepaper anchors**: locate by heading, table and row name, never by line number (the lines move with every merge). Both languages in the same task: `docs/whitepaper/epocha-whitepaper.md` (normative) and `docs/whitepaper/epocha-whitepaper.it.md` (mirror).
