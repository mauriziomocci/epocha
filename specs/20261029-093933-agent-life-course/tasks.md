## Conventions binding every task

- **RED first** in every task that changes behaviour: write the test, run it, watch it fail for the stated reason, then implement. A test never seen failing is not a test. Tasks marked *refactor*, *pin* or *guard* say how the test is proven instead.
- **Mutation proof**, where a success criterion asks for it, is a task of its own: inject the named fault, watch the named test go red, revert, and write the observed failure line in the task line when flagging it.
- **Bars**, restated in every code task as `Bars:`: functions about 40 lines at most and nesting at most 3; no catch-all `except`; errors typed and decided by type; no dead code; no duplicated logic (one way to do each thing, reuse the point the plan names); every constant and threshold cites its source in the docstring or is declared a tunable heuristic; English identifiers; no N+1 query and no query per agent.
- **Reuse statement** in the commit body of every task that adds a function: copy the relevant paragraph of plan.md, "Architectural placement and reuse".
- **One task, one commit**, checkbox flipped in that commit, except inside a **commit group** `G<n>` (plan PD-19): its tasks are done and flipped one at a time and one commit is made at the last task of the group, because the doc-sync rule requires the whitepaper chapter in the same commit as the code. A commit that touches a module of the doc-sync table without changing the model (a refactor, an unused helper) says so in its body and names the chapter it leaves untouched.
- **Commit messages**: Conventional Commits in English through `git-commit-assistant`; no AI reference, no `Co-Authored-By`, no emoji.
- **Escalation**: anything not derivable from this file, the plan and the spec (an unforeseen edge case, a wrong assumption, a symbol that does not match) stops the task and goes to Opus. Never invent.
- **Markers**: `[US1]`, `[US2]`, `[US3]` = user story of the spec. `[Opus]` = judgment or phase-6 task, not for the Sonnet implementer. `[COORD]` = done by the coordinating session that owns the build map.
- **Order**: the phases run in the order below, not in user-story priority. The decision-layer guards of User Story 2 (Phase 2) land BEFORE the selection threshold drops from `adulthood_age` to 10 years (Phase 3): otherwise the branch would, for the commits in between, let a fourteen-year-old choose `move_to` or `buy_property`.
