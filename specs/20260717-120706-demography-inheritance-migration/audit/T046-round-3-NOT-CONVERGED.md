## A pre-existing item surfaced by the re-attack, recorded rather than charged

Attacking conservation at magnitudes and heir counts neither prior round used — 31,500 allocations from 0.01 to 1e15 across seven heir configurations and three rules — found `sum(allocation.values()) != inheritable` for 22.3% of random amounts at 7 heirs and 48.4% at 11, at every magnitude, relative error ~1e-16. Cause: CPython 3.12's `sum()` uses Neumaier compensated summation and computes the true mathematical sum, which differs from `total` by exactly the rounding the last heir's remainder absorption papered over; naive left-to-right re-summation reproduces `total` exactly and never failed in 200,000 trials. This is already documented at `test_inheritance.py:3166-3185` with the same measured rates, independently reproduced here. Raised only because of where the honesty lives: the narrow true guarantee is in a test docstring while `_allocate_with_exact_remainder`'s own docstring at 1666-1673 still asserted the strong claim. Not a round-3 regression, so not charged.
