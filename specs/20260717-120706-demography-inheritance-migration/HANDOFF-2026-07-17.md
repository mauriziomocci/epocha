## Key decisions and why

- **D1 — same-tick double death** lives in `couple.py:dissolve_on_death` (extended to fall back to a couple already dissolved at this same tick), NOT duplicated into `inheritance.py`. Dissolving a couple is couple.py's single responsibility. Signature unchanged; batch state deliberately NOT threaded in. Already implemented (`d1711e6`).
- **D5 — restricted formula evaluator** (`evaluate_derived_formula`): AST walk with a node whitelist, names resolve only against the caller's `symbols` dict, no `eval()`. The whitelist is the security property (SC-006) — never widen it to make a test pass. Already implemented (`48ce6ff`).
- **T003 superseded — whitepaper §4.1 consolidated at closure.** The §4.1 chapter is `frozen-at-commit` (front-matter pin + per-section "as of the pinned commit" status), re-stamped only at merge. Updating §4.1.3 prose while the pin is stale would describe code ahead of its declared commit. The D1 fix is an integration detail that does not change the scientific model, so the doc-sync escape clause applies: code commits carry NO whitepaper edit, and the entire §4.1 delta (couple MISS-4 + inheritance + migration + the frozen-at-commit re-pin to the merge SHA) lands once in T043. Decided by the user 2026-07-17.
- **era_mean/era_sd interim default** (`inheritance.py` `DEFAULT_ERA_MEAN=0.5`, `DEFAULT_ERA_SD=0.15`): the design wants these estimated from the tick-0 population and frozen; that machinery is Plan 4 and no era template declares the data. The code reads a template noise spec if present, else falls back to these named, documented, tunable constants. Documented interim substitute, not a magic number. See Open Questions — needs phase-6 ratification.
- **Deterministic trait ordering** (in `apply_trait_inheritance`): heritable trait names are iterated in heritability-table order then lexicographically sorted personality-only names, NOT via a Python `set`. A set would make the `rng.gauss` draw sequence depend on the process string-hash seed and silently break bit-for-bit reproducibility.
- **scalar-vs-JSONB dispatch by introspection**: a heritable trait whose name is a concrete `Agent` field is written as a scalar attribute; otherwise into `Agent.personality`. Chosen over a hardcoded list so new model fields are handled automatically. This is why `mental_health_baseline` (no matching field) goes to personality — see Open Questions.
- **Commit scope is `config`** for every commit on this branch. The project's declared scopes (`simulation, agents, world, chat, llm-adapter, config`) do not include `demography`; `config` is the consistent fallback used across the branch.
- **No `research.md` / `data-model.md`**: nothing to research (design CONVERGED, zero clarification markers), nothing to model (no schema change). Matches the three most recent Spec Kit features.
